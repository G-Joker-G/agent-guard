# Agent Guard 参赛背书框架：Nadella 七原则 → 功能映射

> 一页纸。用于黑客松作品介绍 / 答辩时引用行业共识做背书。
> 定位：Agent Guard 是"智能供给"之外的"执行权力"层。

## 来源

- 微软 CEO Satya Nadella 2026-10-10 发表《Models as Insider Risks in the Super Intelligence Era》（个人博客 + X @satyanadella 置顶长文），The Verge、Seattle Times 等多家媒体报道跟进。
- **使用边界**：引用的是公开的行业观点，用于说明"我们做的方向和行业共识一致"；不代表 Nadella / Microsoft 为本产品背书。被追问时如实说明。

## 核心论点（一句话）

"We need to separate the supply of intelligence from the authority over it."
（智能的供给，必须和执行的权力分开。）

Agent Guard 就是"权力侧"的那一层：模型只管想、只管规划；**做什么、做到哪一步，由模型之外的网关裁决**。

## 七原则映射

| # | Nadella 原则（转述） | Agent Guard 对应实现 | 演示路径 |
|---|---|---|---|
| 1 | 模型多样性：不让单一模型既做事又自己验算 | 不适用。本产品是执行控制层，不解决模型选型——诚实留白，可列入路线图 | — |
| 2 | 全面观察：每个有意义的动作都要留下防篡改、人类可读的证据。"If it can't be observed, it can't be trusted!" | SSE 实时事件流 + Web 实时运行视图；工具请求、策略理由、待审批动作、执行结果全部可见 | A / B / C / D 全程 |
| 3 | 可验证性：系统要经受攻击、失败和边界测试，而不只跑通 happy path | pytest 23/23；攻击模式（越权调用、prompt injection）内置为可复现演示；审计回放可逐条复核 | B |
| 4 | 独立控制：模型能访问什么、能做什么，规则必须坐在模型外面，模型改不了 | 外部权限网关 `gateway.py` 统一裁决入口 `adjudicate()`；外置策略引擎；5 个 MCP 工具全部走同一网关，外部 Agent 无法绕过。这正是 1970s reference monitor 思想：程序不能绕过或篡改执行其权限的机制 | D |
| 5 | 独立可审计：检查者必须和被检查的智能分离，模型不能同时控制行为和评判证据 | 审计哈希链（防篡改）；审计回放；证据与被检查的 Agent 分离存放 | 审计回放 |
| 6 | 紧急收容：授权人必须能在任务中途随时暂停或关停模型，如紧急制动 | 人工急停 `/api/admin/stop`（需显式恢复）；敏感步骤人工审批（一次一用 + scope 绑定）；执行期间随时可停 | C、A（含审批） |
| 7 | 事件披露：出故障时，受影响的人应及时得到通知和清晰的问题说明 | 人类可读审计日志 + 事件时间线，可作为事后披露的事实基础；完整的对外披露流程超出原型范围 | — |

## 答辩话术（一分钟版）

"我们做的是一个独立于 AI Agent 的执行控制层。Nadella 在 10 月 10 日的文章里提出：要把智能的供给和执行的权力分开，控制必须坐在模型外面。Agent Guard 就是这一思想的工程实现——模型可以想、可以规划，但每一个对外动作（读什么、调什么、发什么）都要经过模型之外的统一网关裁决；人可以随时急停；每一步都留下防篡改的人类可读证据。四条演示路径分别对应：真实 LLM 自主执行（A）、越权与注入被网关真实阻止（B）、执行中人工急停（C）、外部 MCP 客户端同样过网关（D）。"

## 被追问时的诚实回答

- "Nadella 认可你们吗？"→ 没有。这是公开行业观点，我们引用它说明方向一致。
- "模型多样性你们怎么做的？"→ 不在原型范围内，执行控制层与模型选型正交，是后续路线图。
- "事件披露呢？"→ 原型提供事实基础（审计日志+时间线），完整披露流程未做。
