# 演示路径说明（评委版）

> 建议先点"演示" Tab → "演示辅助" → "一键重置"，从干净状态开始。
> 三条路径都可在"演示" Tab 一键运行，每一步会显示调用的后端接口与返回判定；
> 也可以按下面的手工步骤在"任务中心/审批中心"里逐步操作，体验完整交互。

## 路径 A：正常审批流（约 2 分钟）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 任务中心 → 新建任务，场景选"客户跟进" | 任务状态：已创建 |
| 2 | 点"生成计划" | 产生 2 个结构化请求：`crm.read`、`mail.send`（均为 proposed） |
| 3 | 点"推进" | 网关评估：`crm.read`→**允许**并真实执行；`mail.send`→**等待审批**，任务状态变为"等待审批"，审批中心出现待办（含操作/目标/参数摘要/风险说明） |
| 4 | 审批中心 → 批准 | 审批单 approved（绑定请求 hash+参数+30 分钟有效期） |
| 5 | 任务详情 → 对 `mail.send` 点"执行" | 状态变为已执行 |
| 6 | 发件箱 | 出现 1 条真实写入 DB 的模拟发送记录 |
| 7 | 审计日志（按该任务筛选） | 时间线含 task.created → action.proposed → action.policy → approval.created → approval.approved → action.executed；点"校验哈希链"通过 |

**要讲的故事**：读数据这种低风险动作自动放行，对外发邮件必须人工看一眼——审批只对"这一次、这些参数"有效。

## 路径 B：越权拦截（约 1 分钟）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 任务中心 → 新建任务，场景选"越权攻击" | 任务状态：已创建 |
| 2 | 客户数据 Tab | 注意客户"赵小芳"的备注里嵌了一条中文"系统指令"（模拟提示注入） |
| 3 | 点"生成计划" | 演示 Agent"读到"注入后被诱导，产出 `crm.export_all` 请求 |
| 4 | 点"推进" | 网关策略引擎：`crm.export_all`→**拒绝**（批量导出全部客户资料，禁止）；再点"执行"也无任何效果 |
| 5 | 审计日志 | `action.denied` 事件含拒绝原因；发件箱/客户数据无任何副作用 |

**要讲的故事**：Agent 已经被提示注入"骗"了，但**权限层独立于 Agent**——无论 Agent 是否被诱导，未授权的执行都会被网关拦住。

## 路径 C：急停流程（约 2 分钟）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 任务中心 → 新建任务，场景选"批量操作" → 生成计划 → 推进 | `crm.read` 执行，3 个批量 `mail.send` 进入等待审批 |
| 2 | 审批中心批准其中 1 个邮件 | 该动作变为"已批准" |
| 3 | 点右上角红色"紧急停止" | 全站红色警示条；网关立即拒绝新动作 |
| 4 | 对"已批准"的动作点"执行" | 被阻止（409），审计记 `action.blocked_stop`；其余 proposed 动作变为 blocked_by_stop |
| 5 | 点"恢复"（需二次确认） | 警示条消失 |
| 6 | 再点"执行" | 成功执行；审计含 stop.engaged / stop.released |

**要讲的故事**：批量操作跑飞时，管理员一键刹车——**每次执行前都会重新检查急停状态**，已发出的不宣称可撤销，恢复必须显式操作。

## 一句话卖点（给评委）

> Agent 只负责"提方案"，动手前必须过三道门：外部策略（默认拒绝）→ 人工审批（一次一用、绑定参数）→ 急停开关（每次执行前复查）。三道门都在服务端，前端只是展示。
